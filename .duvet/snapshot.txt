  SECTION: [Addressing Issues](#section-6)
    TEXT[!MUST]:    Implementations MUST ensure that all BFD Control packets are
    TEXT[!MUST]:    transmitted over the one-hop path being protected by BFD.
    TEXT[!MUST]:    On a multiaccess network, BFD Control packets MUST be transmitted
    TEXT[!MUST]:    with source and destination addresses that are part of the subnet
    TEXT[!MUST]:    (addressed from and to interfaces on the subnet).
    TEXT[!MUST]:    On a point-to-point link, the source address of a BFD Control packet
    TEXT[!MUST]:    MUST NOT be used to identify the session.
    TEXT[!MUST]: This means that the
    TEXT[!MUST]:    initial BFD packet MUST be accepted with any source address, and that
    TEXT[!MUST]:    subsequent BFD packets MUST be demultiplexed solely by the Your
    TEXT[!MUST]:    Discriminator field (as is always the case).
    TEXT[!MUST]: If the received source address
    TEXT[!MUST]:    changes, the local system MUST NOT use that address as the
    TEXT[!MUST]:    destination in outgoing BFD Control packets; rather, it MUST continue
    TEXT[!MUST]:    to use the address configured at session creation.
    TEXT[!MAY]: An implementation
    TEXT[!MAY]:    MAY notify the application that the neighbor's source address has
    TEXT[!MAY]:    changed, so that the application might choose to change the
    TEXT[!MAY]:    destination address or take some other action.
